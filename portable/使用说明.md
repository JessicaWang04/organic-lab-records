# Organic Lab：有机合成实验记录 Skill

**当前版本：0.1.1 测试版。** 给一篇新的有机合成论文链接、DOI、PDF 或反应截图，即可开始整理。技能使用宿主已有模型；本地工具负责计量、绘图和保存，无需另外配置一套模型 API key。

## 分享给别人：三步开始

1. **分享完整包**：发送构建产物 `dist/organic-lab-records-windows.zip`，不要复制你自己已安装的技能目录或整个 Obsidian 库。
2. **安装**：对方解压后进入 `organic-lab-records` 文件夹，双击 `setup-opencode.cmd`。安装器会安装技能，并为 OpenCode 注册 `/lab`；已有同名命令会保留，不自动覆盖。
3. **开始整理新文献**：重新打开 OpenCode，在自己的项目目录中输入 `/lab 新论文链接` 或 `/lab DOI`。也可以附上新 PDF、截图后发送 `/lab`。未指定范围时，默认整理文章完整主路线。

首次使用需提前准备一个能导入 **RDKit** 的 Python。安装器目前不会自动安装 RDKit；它会检查环境，并尝试补齐缺少的 Pillow、PyMuPDF。Windows 完整包自带 Node，补装 Python 依赖需要网络。没有找到 RDKit Python 时，按下方“Windows 首次配置”指定解释器。

**`/lab` 是随包提供的 OpenCode 自定义命令，不是技能目录自带的通用命令。** 只复制 `organic-lab-records` 技能目录，不等于注册 `/lab`。手动安装的用户可使用宿主的技能调用入口；使用本包安装器即可获得上述短入口，无需抄长提示词。

Codex 用户双击 `setup-codex.cmd`，重新打开 Codex 后，用 `$organic-lab-records` 加论文链接或附件调用。Codex 的安装入口不注册 `/lab`。

分发包不携带作者机器的记录库路径、密钥、`runtime.json`、本机默认配置或实验笔记。对方安装时生成自己的运行时配置，输出到对方的记录库。

## 默认会得到什么

- 获取可访问的论文正文和 SI，保存来源文件、页码及原文依据；访问受限或文件缺失时如实报告。
- 按文献原投料整理完整主路线，每篇新文献建立独立目录；用户指定全部目标或分支时按指定范围整理。
- 生成路线索引、逐步骤 Markdown 实验草稿、计量表、反应 PNG 和可编辑 CDXML；文字提取与结构核对尽早并行，共同中间体复用已核对结构。
- 保留 one-pot、粗品续用和合并产率的文献口径。未知字段留空，原文数值冲突标为待核对。
- 本次实际规模、操作、现象、实测产率和图谱留空，由使用者填写。文献记录只进入参考区。

不能可靠确认的结构会保留原图和具体待核对项。最终报告应列出实际生成的 CDXML 数量与缺失步骤；文件能被 RDKit 读回不等于来源图片中的结构已识别正确。

## 结果保存在哪里

输出位置按以下顺序选择：用户本次明确指定的库、当前已确认的 Obsidian 项目库、本机可选默认库，否则在当前工作目录下建立 `Organic Lab Records`。新用户不会继承作者机器上的 `demo-vault` 路径。

路线位于 `<记录库>/Organic Lab/<自动路线名>/`；宿主会提供真实绝对路径。每篇新文献使用独立路线目录，保留已有笔记与配置。Markdown、PNG 和静态计量表可直接查看，已核对的 CDXML 可在化学绘图软件中继续编辑。

要固定个人输出库，可在已安装技能目录内设置可选的 `local-defaults.json`，填写自己的绝对库路径，例如：

```json
{
  "vault": "D:/MyNotes/OrganicLab"
}
```

这是宿主读取的本机偏好，不能当作 CLI 参数文件使用；当前已确认项目库和本次明确指定位置优先。分享时不包含此文件。

将整座记录库在 Obsidian 中打开，首次仍需允许社区插件。任务会准备配套 `organic-lab-agent` 插件及缺失配置，已有配置予以保留；必要时在 Obsidian 手动启用该插件和 Bases。

## 如何理解“效果”

`SKILL.md` 是入口与核心规则，详细流程、化学核对和工具参数分别放在 `references/workflow.md`、`references/commands.md` 与 `references/tools.json`。说明短不代表工具只有短提示；模型需要按入口继续阅读相关参考文件。

最终效果仍取决于宿主模型的图文理解、工具执行能力及来源质量。应分别检查：步骤是否齐全、投料与操作是否有原文依据、结构连接和立体信息是否正确、CDXML 是否实际生成，以及待核对项是否完整。不能仅用文件数量或工具运行成功评价文献整理质量。

| 验证对象 | 当前边界 |
| --- | --- |
| 本地工具与绘图流程 | 已有回归检查和本机截图任务验收记录；说明文件更新不构成新的验收 |
| OpenCode `/lab` | 已提供自动注册入口；仍需在真实 OpenCode 中验收完整的新文献任务 |
| 文献结构识别准确率 | 尚无覆盖复杂结构、差向异构体与多篇新文献的正式准确率基准 |
| Qwen、DeepSeek 与其他宿主模型 | 使用宿主已配置模型；尚未完成同一批文献的质量、耗时与费用对比 |
| WorkBuddy、跨平台与全新电脑 | 有适配入口或运行说明，完整安装到交付尚待验收 |
| Obsidian 桌面交互 | 文件和配置准备成功不代表真实桌面交互已经验收 |

版本 0.1.1 改善了新文献默认行为、结构任务的执行顺序和短入口安装；完整多模型提速调度仍不是本版已经实现并实测的功能。不要把安装成功、`doctor` 成功或一次简单截图成功解释成所有文献都能准确完成。

## 使用边界

- **交付实验草稿**：结构、立体化学、计量及条件仍需核对；不保证反应成功，也不预测新底物的反应结果。
- **保留缺项和冲突**：截图模糊、复杂结构或资料截断时，不猜测缺失结构、投料、密度、纯度、后处理等信息。
- **规模按步骤绑定**：第一步的实际规模不自动变成后续每一步的投料，不用文献产率推算后续实测规模。溶剂体积保留文献参考口径。
- **用户填写实测结果**：文献操作、产率、现象和图谱不替代本次实际实验记录。
- **遵循宿主权限**：本地执行和文件访问需要宿主允许；宿主模型的用量与费用正常计算。本地工具不额外调用模型 API。
- **保护已有内容**：现有同名技能目录或 `/lab` 命令不会被安装器自动覆盖。发生冲突时查看安装提示，审阅后再更新。

## Windows 首次配置

Windows 完整包随附 Node 24。WorkBuddy 轻量包不含 Windows 二进制，需另有可用 Node 20 或更新版本。选中的 Python 必须能导入 RDKit、Pillow 和 PyMuPDF。

双击 `setup-codex.cmd` 或 `setup-opencode.cmd` 安装到相应宿主；`setup.cmd` 是 Codex 入口的别名。只配置解压包用 `configure-local.cmd`。双击入口会检查环境，并仅在缺少 Pillow、PyMuPDF 时尝试安装这些依赖；不会安装 RDKit、改系统 PATH、API 设置或全局脚本执行策略。

需要明确指定 Python 时，在完整包所在目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\organic-lab-records\setup.ps1' -Python 'C:\path\to\python.exe' -Host opencode
```

使用 Codex 改为 `-Host codex`；只配置当前解压包用 `-Host none`。省略 `-Python` 时，程序按环境变量、上次配置、系统 `python/python3` 和 `py -3` 查找能导入 RDKit 的解释器。

直接运行 PowerShell 安装脚本默认只检查依赖。需要向选中的 Python 环境补装缺少的 Pillow、PyMuPDF 时加上 `-InstallDependencies`：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\organic-lab-records\setup.ps1' -Python 'C:\path\to\python.exe' -Host opencode -InstallDependencies
```

运行时配置写入本包及安装目录的 `runtime.json`。配置完成后可运行工具检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\organic-lab-records\scripts\run-lab.ps1' doctor
```

`doctor` 检查运行环境，不测试宿主模型的论文理解或结构识别准确率。依赖失败时先按提示补齐，再重新安装；失败回执不能视为安装成功。

## 配套 Obsidian 插件

对话任务调用 `prepare-vault`，把随包预构建的插件与缺失配置准备到目标库，保留已有配置。最低 Obsidian 1.11.4；图库使用 Bases 核心插件。首次打开新库仍需允许社区插件，并按已有库的配置状态启用所需插件。

分发目录另提供 `organic-lab-obsidian-plugin.zip`，供手动安装：把其中的 `organic-lab-agent` 文件夹解压到目标库的 `.obsidian/plugins/`，再在社区插件设置中启用。该包只含程序，不包含本机设置、密钥或笔记。查看静态记录无需启用交互插件；输入规模、填写实测结果和新建重复实验等交互功能需启用插件。

## 其他宿主与平台

| 宿主 | 安装与调用 |
| --- | --- |
| Codex | `setup-codex.cmd` 安装到 `CODEX_HOME/skills/organic-lab-records`；未设置 CODEX_HOME 时使用用户目录下 `.codex/skills/organic-lab-records`。调用 `$organic-lab-records` |
| OpenCode | `setup-opencode.cmd` 安装到用户目录下 `.config/opencode/skills/organic-lab-records`，并注册 `.config/opencode/commands/lab.md`。项目内技能目录也可手动安装，但 `/lab` 需另行注册 |
| WorkBuddy | 使用构建生成的轻量格式包，通过技能界面“添加技能 → 上传技能”导入；实际导入与完整生成尚未实测 |

WorkBuddy 包采用其所需的元数据格式，并复用通用包本地工具。导入 Skill 不等于安装 RDKit 或 Node；当前不承诺仅有 RDKit 就能在 WorkBuddy 中运行。官方资料未确认通用包复制到某个 `.workbuddy` 目录即可自动发现，因此使用官方导入入口。

macOS/Linux 需系统 Node 20 或更新版本和已有 RDKit Python，在当前终端指定解释器：

```sh
export ORGANIC_LAB_PYTHON='/absolute/path/to/python'
sh '/path/to/organic-lab-records/scripts/run-lab.sh' doctor
```

随后按宿主技能入口与 `references/commands.md` 使用本地工具。Windows 双击安装和 `/lab` 自动注册说明不能直接视为其他平台已经完成验收。
